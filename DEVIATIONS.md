# Deviation register

Every difference between LynnDrum and the firmware it derives from. A deviation without a pinning test is a bug.
T0 = bit-exact against the reference harness; the harness itself is the unmodified upstream plus H-patches.

## Reference harness (Tools/ref-harness) - details in `docs/ref-harness.md` §4

| ID | What | Pinned by |
|---|---|---|
| H1 | `calcNoise` reads CPU overflow flag -> emulated signed overflow (effect on MCU unknown) | golden manifest |
| H2 | wavetables get a guard row (`[k][1024]` read in bounds) | golden manifest |
| H3 | `parameterArray[0]` points at a zero byte (MCU reads address 0) | golden manifest |
| H4 | kit parameter 127 / CC#0 dropped (upstream writes 64 KiB past a 255-byte array) | scenario `sweep_PAR_BANK_CHANGE` excluded; `lxr_param` test |

| H6 | xorshift32 replaces the hardware TRNG | seeded scenarios |
| H7 | out-of-domain enum values excluded from the catalogue | generator |
| H8 | Euclid 64-step rotation mask shift guarded | `euclid_64_17_5` |

## lxr_core (Source/Engine/lxr_core)

| ID | What | Why | Pinned by |
|---|---|---|---|
| L1 | Global state lives in `LxrEngine`; upstream identifiers resolve through macros against a thread-local "current engine" set by every `lxr_*` entry point. Function bodies are textually identical to upstream. | multi-instance safety with minimal diff | `Tools/compare/test_instances` (interleaved + concurrent), null test |
| L2 | `MidiParser.c` reduced to `lxr_param.c` (`midiParser_ccHandler` + helpers, body byte-identical); MIDI/UART/USB/MTC parser omitted | not part of the instrument core | null test |
| L3 | Jack-detect GPIO replaced by "all jacks connected" (`mixer.c`: four lines) | no hardware | null test |
| L4 | Fader gain, tempo, mute mask, RNG are engine fields (`adc_getFaderVolume`, `seq_getBpm`, `seq_setMute`, `HAL_RNG_*` macros) | host services | null test |
| L5 | `menu_*`/`uart_*`/`seq_sendMidi*` side effects of the handler compile to nothing | UI/MIDI-out concerns | null test |
| L7 | `LXR_KIT_BYTES` = `END_OF_SOUND_PARAMETERS` = **247** (earlier docs said 228; that was a stale comment in upstream). `lxr_load_kit` had loaded only 228 until P5 (no audible effect: the init kit has zeros there). Now `_Static_assert`-checked. | correctness | null test, `host_tests` |
| L6 | H1-H5, H8 patches are baked into the derived sources (they are applied by `make_core.py`) | portability | null test vs harness |

Phase-2 status: **T0 holds for all 818 catalogue scenarios** (`Tools/compare/null_test.py`), UBSan-clean.
Not yet done in Phase 2: the base/override/effective split for modulation and p-locks (needed by S1/S2/P5); until then
`lxr_param` is the unmodified write-through path and p-locks must replay the original restore-then-write sequence.

## lxr_seq (Source/Sequencer/lxr_seq) - generated by `Tools/port/make_seq.py`

| ID | What | Why | Pinned by |
|---|---|---|---|
| Q1 | Same technique as L1: state in `LxrSeq`, upstream identifiers via macros to a thread-local current sequencer (`lxrseq_macros.h`); member names carry an `m_` prefix so macros cannot hijack member access | multi-instance | `test_seq_instances` (alone / interleaved / 2 threads), T0 |
| Q2 | **Time is the firmware's 0.25 ms systick, injected by the host (`lxrseq_tick`), one poll = one sub-tick, exactly like `seq_tick`.** No re-implementation of the clock. Polling once per 64-frame engine block reproduces the firmware's timing (incl. shuffle, decision D8). Host sync/locate/loop (S2) sit *around* this core. | faithful, and the shuffle behaviour comes for free | 75 event streams (`golden/seq`) incl. `poll6`, `shuffle_*` |
| Q3 | Effects leave through `LxrSeqSink` (trigger, p-lock cc writes, kit change, tempo); `voiceControl_noteOff`, MIDI/USB/UART out, LED/menu/button/trigger-out calls compile to nothing | engine-agnostic; UI/hardware | T0 |
| Q4 | MIDI-out functions (`seq_sendMidi*`, `seq_midiNoteOff`, ...) removed from the derived source | not applicable | compiles |
| Q5 | Local variables named `isStepShuffled` renamed `isStepShuffledLocal` (macro hijack) | mechanical | T0 |
| Q6 | `automationNode.c` lives only in lxr_seq (restores/writes p-locks through the sink); removed from lxr_core | one definition per symbol, clean boundary | link test |
| Q7 | **Probability/rng: the sequencer has its own xorshift32 stream** (seed via `lxrseq_set_seed`); upstream shared one TRNG stream with the noise oscillators. Event streams are identical when audio is not rendered; rendered noise differs in scenarios that use probability/active steps with noise voices (15 of 75 `play` scenarios). | reproducible bounces independent of audio | `play` comparison, S4 |
| Q8 | Euclid length 16 -> stored 0 -> `% 0` in `seq_processFlam` (upstream bug, found in S0) is **not yet fixed in lxr_seq** (reference behaviour kept; scenarios normalise). Fix = treat 0 as 16 everywhere - to be done with its own pinning test. | | `euclid_16_*` |

Remaining sequencer deviations from `docs/lxr-sequencer.md` §7: S1 (clock) is now Q2; S2 MIDI clock slave kept in code but unused; S3 host-position anchoring and S8 float tempo belong to the S2 stage (SeqClock/SeqTransport);
S5 is **superseded by decision D8 (2026-10-24): shuffle reproduces the original**.

## Host layer (Source/Host, Source/Plugin)

| ID | What | Why | Pinned by |
|---|---|---|---|
| S8 | Float host tempo: the sequencer's injected clock is scaled by `hostBpm / (60000/floor(60000/round(hostBpm)))`. The firmware itself runs at that *effective* integer-division tempo (87 -> 87.1 BPM), so reference-mode tests keep the original behaviour. | host grid accuracy | `host_tests` sequencer grid |
| R1 | Engine runs at 44 140 Hz; a 64-tap Kaiser polyphase resampler converts to the host rate (not bit-exact by design, tier T2) | arbitrary host rates | `host_tests` resampler |
| R2 | DAC1 and DAC2 are summed into the stereo output (hardware had two stereo outputs) | single stereo bus for now | - |
| R3 | Sequencer start/stop/locate/loop follow the host and re-anchor to its PPQ grid (S3 of `lxr-sequencer.md`); only free mode starts at step 0. A shuffle delay already pending when a locate happens is dropped. | host workflow | `transport_tests` |

## Parameters (P5)

| ID | What | Why |
|---|---|---|
| P1 | Host parameter ranges come from the firmware's own datatype table (`parameter_dtypes[]`, positional: row i = parameter i) and menu lists, not "0..127 for all". 233 sound parameters are exposed (all of `PAR_*` below `END_OF_SOUND_PARAMETERS` except None, NRPN address bytes, Bank change, Unused, Reverb type (compiled out), Morph kit dest). | out-of-domain values are undefined in the original |
| P2 | Parameters are 7-bit steps (hardware resolution); changes are handed to the engine once per audio block at offset 0 (no intra-block automation, no smoothing - like the firmware). | fidelity, deviation from sample-accurate automation |
| P3 | Velocity / LFO "target" parameters are choices over the firmware's 229-entry `modTargets[]` list and use `lxr_set_mod_target` (same effect as the front-panel messages). | engine API |
| P4 | Display names are generated + a small rename table (`Tools/params/gen_params.py`); parameter ids are the lower-cased `PAR_` names and are stable. | host automation lanes must not change |
| P5 | Defaults = the clean-room *Init* preset (`Presets/factory/init.lynnpreset`); no upstream kit data is used by the plugin. | NOTICE |
